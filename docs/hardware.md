# Отчёт о конфигурации машины и бенчмарке

## Конфигурация окружения

| Компонент | Значение |
|---|---|
| Процессор | Apple M4 Pro, 14 ядер |
| Оперативная память | 48 ГБ объединённой памяти |
| Операционная система | macOS 26.2 |
| Python | 3.12.14 |
| uv | 0.12.10 |

Профиль машины по таблице курса: **Mac Apple Silicon, 16 ГБ+**. Для этого
профиля выбрана рекомендованная модель `Qwen/Qwen3-1.7B`.

Имя выбранной модели указано только в `params.yaml`.

## Параметры бенчмарка

| Параметр | Значение |
|---|---|
| Модель | `Qwen/Qwen3-1.7B` |
| Тип данных | `bfloat16` |
| Промпт | «Объясни, что такое MLOps, в трёх предложениях.» |
| Максимум новых токенов | 200 |
| Температура | 0 |
| Seed | 42 |
| Режим рассуждений Qwen3 | выключен |
| Число прогревочных запусков | 1 |
| Число измеряемых запусков | 3 |

Прогревочный запуск выполнен после загрузки модели и не включён в
расчёт скорости. Для каждого из трёх измеряемых запусков использован
отдельный таймер. Итоговая скорость вычислена как медиана отдельных
значений `tokens/sec`.

## Результаты

| Метрика | Результат |
|---|---:|
| Время загрузки токенизатора и модели | 2.26 с |
| Скорость, запуск 1 | 41.72 токена/с |
| Скорость, запуск 2 | 41.87 токена/с |
| Скорость, запуск 3 | 42.15 токена/с |
| Медианная скорость | **41.87 токена/с** |
| Пиковая RSS-память процесса | **4455.5 МБ** |

Пиковая RSS измерена через `resource.getrusage`. Это максимальная
резидентная память процесса за всё время его работы, а не единичный
снимок памяти после генерации.

При проверочном запуске модель сгенерировала 51 новый токен. Значение
`max_new_tokens: 200` задаёт верхнюю границу, поэтому остановка раньше
200 токенов после генерации специального токена завершения корректна.

## Найденные и исправленные дефекты

### 1. Имя модели было захардкожено

**Проблема.** Имя `Qwen/Qwen3-0.6B` было записано строкой в трёх местах:
в загрузчике модели, в сообщении `generate.py` и в JSON-отчёте
`bench.py`.

**Как проявлялось.** Изменение `model.name` в `params.yaml` не меняло
фактически загружаемую модель. Кроме того, консольный вывод и отчёт могли
указывать Qwen3, даже если в конфигурации была выбрана другая модель.

**Исправление.** Все три места теперь читают имя из
`params["model"]["name"]`. `params.yaml` стал единственным источником
имени модели.

### 2. Зависимости не были зафиксированы

**Проблема.** Прямые зависимости в `pyproject.toml` были указаны без
версий, например `torch` и `transformers`. Зависимость `psutil` также
отсутствовала в исходной конфигурации.

**Как проявлялось.** При установке в разное время `uv` мог выбрать разные
версии библиотек. Это делало окружение невоспроизводимым и могло привести
к различиям поведения локально и в CI.

**Исправление.** Для всех прямых зависимостей указаны точные версии, а
полное дерево зависимостей сохранено в `uv.lock`.

### 3. Бенчмарк смешивал загрузку и генерацию

**Проблема.** Единственный таймер запускался до загрузки модели и не
перезапускался перед отдельными генерациями. Время каждого следующего
запуска получалось накопительным, `load_time_sec` всегда оставался равен
нулю, а прогрев отсутствовал.

**Как проявлялось.** Рассчитанная скорость была занижена и не отражала
реальную производительность генерации. В неё попадали загрузка модели и
предыдущие запуски.

**Исправление.** Время загрузки измеряется отдельным таймером. Затем
выполняется один прогревочный запуск. Каждый из трёх рабочих запусков
получает собственный таймер, после чего скорость рассчитывается как
`число новых токенов / время запуска`. Итогом служит медиана трёх
значений.

### 4. Генерация не была воспроизводимой

**Проблема.** В конфигурации использовалась температура 0.7, а готовая
функция `set_seed` не вызывалась из точки входа генерации.

**Как проявлялось.** При включённом сэмплировании последовательные
запуски могли давать разные ответы на один и тот же промпт.

**Исправление.** Температура установлена в 0, поэтому используется
детерминированный жадный поиск. Перед загрузкой модели и генерацией
вызывается `set_seed(params["generate"]["seed"])`, фиксирующий генераторы
Python, NumPy и PyTorch.
