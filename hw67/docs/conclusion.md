# ДЗ 6+7: протокол и результат

## Протокол, закреплённый до измерения

Продолжение CLI-проекта ДЗ 4–5. База `Qwen/Qwen3-1.7B` соответствует
сохранённым тензорам ДЗ 4. У всех шести конфигураций одинаковы seed 42,
train-пул 32, val 8, четыре шага оптимизатора, batch 1 и accumulation 2.
Меняются только lr, ранг и target_modules. Test не используется для выбора.
Порог выбора кандидата: `final_val_loss/base_val_loss <= 1.0`.

Golden содержит 50 самостоятельно составленных вопросов с тремя вариантами
ответа по пяти темам, отсутствующим в полном train: fd, yq, lsblk, ethtool,
Neovim. Каждая тема целиком образует группу; в каждом срезе десять вопросов.
Позиции правильных меток меняются заранее. Полный индекс содержит 3497
исходных train-вопросов; соответствие их id тензорам проверено при подготовке.
Вопросы и эталоны проверены ассистентом по указанным руководствам. Проверка
человеком не заявляется. Проверка точных совпадений и group_id не обнаружила
утечки; смысловые совпадения между разными инструментами она не исключает.

Срезы выбраны до генерации: `file_search` проверяет поиск файлов,
`structured_data` — работу с YAML, `editor` — редактирование конфигураций,
`storage` — диагностику дисков, `network` — диагностику сетевого оборудования.
Последние два критические: неверный совет при диагностике инфраструктуры
может привести к неверным операционным решениям. Срезы здесь не пересекаются;
общий n равен 50, behavioral в него не включён.

Обе модели получают одну system-инструкцию из `evaluation/params.json`,
seed 42, greedy decoding (`do_sample=False`), максимум 32 новых токена,
`enable_thinking=false`. Эталон не передаётся модели. Ответ принимается
только как JSON с единственным строковым полем `answer` из choices.
Три отдельных behavioral-кейса проверяют формат, перефраз с перестановкой
вариантов и отказ на просьбу сочинить стихотворение вне темы CLI.

Гейт требует отсутствия ошибок генерации, отсутствия ухудшения общей accuracy
и format_rate и accuracy каждого критического среза; все behavioral-кейсы
должны быть верными. Допуск регрессии равен нулю. Baseline не меняется
автоматически.

Это проверка отказа гейта, а не дополнительная оценка модели.

## Ограничения и следующий шаг

Небольшой MCQ-набор проверяет выбор метки, а не исполнение команд,
безопасность произвольных советов или генерацию Bash в свободной форме.
Группы инструментов отделены от train; общий pretrained-корпус Qwen нам
неизвестен. Это локальная оценка разработки, не независимый аудит.
Метрики сходства слов не различают `-l` и `-c` по смыслу: почти одинаковые
строки могут означать разные операции, а равнозначные команды могут
выглядеть по-разному. Строгий scorer здесь проверяет эталонную метку и формат.

Модель-судья помогла бы разбирать свободные ответы и допустимые альтернативы,
но может предпочитать многословие, известную модель или первую позицию,
ошибаться в редких флагах и воспроизводить собственные заблуждения. Нужны
слепые имена моделей, перестановка A/B, фиксированная рубрика и проверка
спорных случаев человеком. Judge и платные API в этой работе не использовались.

Следующий шаг: разобрать путаницу fd/ethtool, расширить отдельный development
набор и улучшить модель при равном бюджете сравниваемых конфигураций.
Текущий golden, baseline и пороги ради принятия не менялись.
